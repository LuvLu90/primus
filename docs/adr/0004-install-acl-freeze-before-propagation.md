# 0004：安装权限传播前冻结并检查程序树

- 日期：2026-11-02
- 状态：采用

## 背景

PR #35 的安装目录加固先用 icacls 修改父目录，再检查程序文件硬链接。
即使没有 `/T`，可继承 ACE 也可能传播到子文件；硬链接共享安全描述符，因而会修改安装目录外的目标。
单纯提前扫描也不足以防止扫描与修复之间的路径替换。

## 决策

MSI 的安装脚本（当时与 NSIS 共用；NSIS 已于 ADR 0007 停发）使用 `CreateFile` 的 `OPEN_REPARSE_POINT` 与目录打开标记，
申请读取数据/列目录及安全描述符权限，只共享读取，保持句柄直到修复完成。
仅元数据访问不足以提供期望的共享冲突检查，因此访问掩码必须包含 `FILE_READ_DATA` / `FILE_LIST_DIRECTORY`。

目录先用 `SetKernelObjectSecurity` 设置自身的所有者与受保护 DACL，不向子项传播；
逐级冻结后枚举子项，固定文件句柄后检查链接数。全部检查成功后才调用 icacls 重置程序文件权限。
检查或打开失败即拒绝安装；不在失败时恢复不安全权限。

### 修订：读取共享不是 ACL 锁

Windows 原生回归证实：安装前取得、允许全部共享的 `READ_CONTROL | WRITE_DAC` 句柄，
在目录 DACL 收紧后仍可修改它。不能依靠共享模式或重复检查来撤销这种授权。
因此仅复用所有者为 SYSTEM/Administrators、普通主体至多读执行的可信对象；不就地修复不可信旧对象。
非空不可信安装目录直接拒绝，保留其数据；空的不可信根目录删除后原子创建新安全对象，
旧句柄仅指向旧对象，删除或创建失败即拒绝。程序树同样在权限修改前检查准入。
该检查不声称能证明任意对象的历史权限从未被管理员改变；曾被管理员放宽权限的旧安装应改用新目录。
父目录须预先存在且通过检查，不递归创建缺失祖先。

## 验证与代价

Windows 本地回归验证原生 API 不修改可继承的外部硬链接安全描述符，且持有的目录和文件不能重命名、删除替换。
MSI 冒烟保留硬链接目标的继承并检查其所有者、DACL 和内容不变。
安装期间占用的句柄数量与已有程序树大小成正比；已有冲突访问句柄会使安装失败，需关闭占用进程后重试。
